# wekatester customize (-C) + generated layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Tasks are contract-level: each names files, interfaces, binding requirements, and the tests to write. TDD is mandatory (failing tests first, RED evidence, then green). Steps use checkbox syntax for tracking.

**Goal:** Layout becomes a generated, barrier'd first jobfile on every run; `-C` adds a guided field-customization workflow; the CLI becomes case-insensitive and gains `-r` fast-track, `-n` dry-run, `-g` regen, and `--`.

**Authority:** docs/superpowers/specs/2026-07-31-wekatester-auto-mode-design.md — sections "CLI amendments (2026-08-07)", "Layout phase (all runs)", "Customize workflow (-C)". Where this plan and the spec disagree, the spec governs.

**Architecture:** unchanged — single-file bash orchestration, stdlib-python heredocs for transformation, macOS bash 3.2-compatible, no new dependencies, never suppress stderr. README `# Usage` must stay byte-identical to `./wekatester -h` (suite-enforced).

## Global Constraints

- Spec's prompt primitive design is binding (fd-redirect `read`, never `read -u`; per-char escape drain; whole-second timeouts; `/dev/tty` via `WEKATESTER_PROMPT_TTY` seam; `PROMPT_IN_FD`/`PROMPT_OUT_FD` test seam).
- Layout marker line format, verbatim: `# wekatester-layout: generated sha256=<hex>` (hash of the normalized body: the file minus the marker line, trailing whitespace stripped).
- Generated layout filename, verbatim: `000-wekatester-layout.job`.
- Flag matrix (spec "Regeneration flag matrix") and -C flow order (spec "Customize workflow") are binding requirements, not suggestions.
- All 111 existing tests must stay green through every task.
- No lab is currently available (shrw destroyed): Task 7 is a documented checklist executed later; nothing else may depend on live hosts.

### Task 1: CLI rework

**Files:** wekatester (parse_args :203, usage :172, summarize call sites), tests/test_wekatester.sh, README.md (Usage block only — full README rewrite is Task 6, but the byte-sync test forces the Usage block to move in lockstep here).

**Contract:**
- Case-insensitive option matching: normalize the option token (short letter(s), long name) to lowercase before the `case`; never normalize values or attached arguments. `-v`/`-V` both mean verbosity (repeatable); version becomes `--version` (long-only).
- Remove `-r <items>`: `-s` always summarizes all metric groups (summarize's per-run report_directive behavior is untouched; only the CLI filter dies). `-s file -r anything` is now an unknown-option error for `-r`'s old form... `-r` is reassigned:
- New booleans: `-r` (FAST_TRACK=1), `-n` (DRY_RUN=1), `-g` (REGEN_LAYOUT=1).
- `--` separator: all subsequent tokens append to HOSTS verbatim (even `-`-prefixed).
- `-c`/`-C`: attached value (`-Cmyset`, and `--customize[=name]` long form) sets CUSTOMIZE=1 + CUSTOM_SET="myset". Bare `-C` sets CUSTOMIZE=1 and records C_CANDIDATE="<next bare non-option token>" WITHOUT consuming it (it stays in HOSTS provisionally; Task 5 resolves it at preflight). With `--` present and a bare pre-`--` token following `-C`: that token IS the set name (consumed, not a host); a second such token = usage error.
- Track WORKLOAD_EXPLICIT=1 when -w was given (Task 5 needs it for the recopy rule).
- Usage-error combinations enforced in parse or immediately after: `-C` with `-s`.
- usage() updated (synopsis + option list; document case-insensitivity in one line); README Usage block regenerated byte-for-byte.

**Tests (write first):** case-insensitive short (`-D /x` = `-d /x`) and long (`--AUTO=MAX`); `-V` increments verbosity; `--version` prints version; `-r`/`-n`/`-g` set their globals; old `-s x -r items` form errors; `--` puts `-weird` into HOSTS; `-Cmyset` sets CUSTOM_SET; bare `-C h1` leaves h1 in HOSTS and records C_CANDIDATE=h1; `-C name -- h1` consumes name as set; `-C a b -- h1` usage error; `-C` with `-s` dies; WORKLOAD_EXPLICIT set only when -w given. Existing parse tests updated where the -v/-V and -r semantics changed — every other existing test must pass unmodified.

### Task 3: Layout generator + shipped-jobfile notes

**Files:** wekatester (new `generate_layout <setdir> <outdir>` bash function wrapping a python3 heredoc), all 24 files under fio-jobfiles/*/, tests/helpers.sh (layout fixtures), tests/test_wekatester.sh.

**Contract (spec "Layout phase" bullets 1-2):** reads `[0-9]*` jobfiles in setdir, skips files whose first lines contain the layout marker OR named `000-wekatester-layout.job`; groups by filename_format (absent → `__default__:<file>` key); per namespace: numjobs = max across members (int), nrfiles = max (default 1), filesize = max (parse fio suffixes; if only `size=` present use the capacity model's numjobs×size fallback semantics for footprint sanity but emit filesize from the max size/numjobs... if no per-file size derivable, emit the namespace section without filesize and warn); emits `<outdir>/000-wekatester-layout.job`: marker line first, `[global]` with directory (copied from the set or placeholder — staging overrides it anyway), create_serialize=0, ioengine (most common in the set), then per-namespace `[layout-<n>]` sections: create_only=1, blocksize=1Mi, filename_format, filesize, nrfiles, numjobs. Deterministic output (stable namespace ordering) so the sha256 pristine hash is meaningful. Hash computed over normalized body (all lines except the marker, trailing whitespace stripped) and embedded in the marker.
- Shipped jobfiles: insert one comment line after the `# report` directive (or after line 1 when absent): `# NOTE: file layout is normally handled by the auto-generated 000-wekatester-layout job; the create section below remains for standalone fio use.` All 24 files; do not touch anything else in them.

**Tests (write first):** two-file fixture sharing one namespace → single section with max numjobs; two distinct namespaces → two sections; absent filename_format → per-file namespaces; nrfiles/filesize maxima; marker present and hash verifies (recompute in test via python or shasum over the normalized body); regeneration over an existing pristine file is byte-identical (determinism); generator skips an existing layout file as input; smoke set fixture works (flat namespace). ### Task 4: Runtime layout integration

**Files:** wekatester (stage_jobfiles :780, stage_variants :749, auto_tune heredoc :462+, capacity block :678, run_jobs :813), tests.

**Contract (spec "Layout phase" bullets 3-6):**
- stage_jobfiles: after discover_jobfiles, if no member is a layout file (marker or reserved name), `generate_layout "$JOBFILE_SRC" "$WORK_DIR/gen"` and prepend `000-wekatester-layout.job` to JOBFILES; staging (both auto and non-auto paths) must stage that generated file for every host alongside the set's files (non-auto: same directory-override awk; auto: tuner input includes it — pass the gen dir or copy the file into the tuner's view; implementer's choice, document it).
- Tuner: a layout-marker file gets corrections only (directory, cpus_allowed) — never tier rules. At tier=max, when the layout file is pristine (hash verifies), REPLACE its per-host staged variant's namespace sections with ones re-derived from that host's already-tuned sibling variants (same grouping/max logic as the generator — reuse, don't duplicate: the tuner may import the same helper functions since both live in python; if they're separate heredocs, factor the shared logic into the layout heredoc invoked per host, or duplicate minimally with a comment naming the twin). Non-pristine: stage as-authored + one-time warn "user-edited layout job may not cover auto-tuned namespaces".
- Capacity block: skip layout-marker files when computing required.
- run_jobs: for layout jobs (marker), skip summarize; wrap the run in a duration measurement and log `layout: laid out in <X>s across <M> host(s)`. The missing-host guard doesn't apply (no summarize call). Result JSON still written (harmless, consistent).

**Tests (write first):** stage fixture without layout → JOBFILES[0] is the generated name, staged per host in both auto (tuner fixture) and non-auto paths; with a set-provided layout file → not regenerated, stays first by sort; tuner: layout file at max gets cpus_allowed but NOT numjobs tier rewrite; pristine layout at max → staged variant contains wt-small namespace section (fixture: one iops job so the tuner redirects it); edited layout (corrupt the hash) at max → variant byte-equals source (modulo corrections) + warning on stderr; capacity: fixture where counting the layout file would double required → asserted value proves it's skipped; run_jobs: layout job produces the `layout:` log line and no summary lines (drive via stubbed transport fixtures as existing run tests do... if no existing run_jobs unit test pattern exists, test the helper that decides skip-vs-summarize plus the log formatting).
